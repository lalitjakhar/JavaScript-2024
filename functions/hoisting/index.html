Step 4 · Functions

Hoisting

Call before you define? Function declarations are "hoisted" to the top — but expressions and arrows are not.

Why hoisting matters? Avoid errors. Know when you can call functions before they're written in the code.

1. Function declaration — hoisted

You can call it before the definition!

hello(); // Works! function hello() { return "Hello world"; }
Result…

2. Function expression — NOT hoisted

Calling before definition throws an error.

// greet(); // ❌ ReferenceError const greet = function() { return "Hello!"; };
Result…

3. Arrow function — NOT hoisted

// welcome(); // ❌ ReferenceError const welcome = () => { return "Welcome!"; };
Result…

4. Why hoisting happens

JavaScript moves function declarations to the top during compilation. Variables (const, let) are not hoisted the same way.

// Behind the scenes: function hello() { ... } // Moved to top hello(); // Now safe to call

Best practice: Define functions before you call them.
