Step 5 · Under the Hood

How JavaScript Works

JS runs in two phases: compilation (memory setup) then execution (line by line). Understanding this helps you predict hoisting, scope, and closures.

Why it matters: Before any code runs, JS scans for variables and functions, giving them memory. That's why you can call functions before they're defined.

Global execution context

When your script starts, JS creates a global execution context with the window object and this.

console.log(this); console.log(window); console.log(this === window); // true (in browsers)

Hoisting in action

Variables declared with var are hoisted (moved to top) and initialized to undefined. Functions are fully hoisted.

console.log(firstName); // undefined var firstName = "Lalit Jakhar"; console.log(firstName); // "Lalit Jakhar" console.log(myFunction); // [Function] function myFunction() { return "this is my function"; }

let and const are hoisted but not initialized — accessing them before declaration throws a ReferenceError. Prefer const and let over var.
