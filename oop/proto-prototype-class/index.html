__proto__ vs prototype & class syntax

Objects have __proto__ (link to parent). Functions have .prototype (blueprint for instances). Classes are just syntactic sugar over this system.

Key idea: new creates an object with __proto__ pointing to the constructor's .prototype.

Factory pattern with shared methods

function createUser(firstName, age) { const user = {}; user.firstName = firstName; user.age = age; user.about = function () { return `${this.firstName} is ${this.age} years old.`; }; user.is18 = function () { return this.age >= 18; }; return user; } const user1 = createUser("lalit", 18); console.log(user1.about()); console.log(user1.is18());

Modern: class syntax

Classes do the same thing internally but with cleaner syntax.

class User { constructor(firstName, age) { this.firstName = firstName; this.age = age; } about() { return `${this.firstName} is ${this.age} years old.`; } is18() { return this.age >= 18; } } const user = new User("lalit", 18);

Prefer class syntax in modern code. It's clearer and less error-prone than manual prototype wiring.
